# Certified selection ordering for the complete R(5,5;43) M=214 OPB

## Result and scope

This directory turns the complete normalized M=214 OPB from Discovery Net
height 2505 into an equisatisfiable, symmetry-reduced OPB and emits a standard
VeriPB 3.0 transformation proof.  VeriPB 3.0.2 checks the proof against both
the pinned input and generated output and reports
`VERIFIED OUTPUT EQUISATISFIABLE`.

This is a certified preprocessing step, not a SAT or UNSAT result.  It does not
select any pair of 21-vertex cores, split the branch, or establish a new Ramsey
bound.  The 168 MB input/output formulas and the generated 6.4 MB proof are
reproducible operational state and are intentionally not committed.

The input formula must have SHA-256

```text
88aa294709836a0a707b2203da2176d420a3608353db21cc741dfa9bedf89a58
```

and is generated by the sibling `ramsey_r55_m214_complete_formulation`
directory.

## Selection-order theorem

Fix the normalized anchor 13 and its four non-anchor cells

```text
P0={0,...,5}, P1={6,...,12}, P2={14,...,28}, P3={29,...,42}.
```

For a vertex `v`, let `d_j(v)` be its red degree into `Pj`, put
`a_v=d_0(v)+d_1(v)`, and define

```text
K(v)=4096*a_v + 256*d_0(v) + 16*d_2(v) + d_3(v).
```

Equivalently, the implementation uses cell weights `(4352,4096,16,1)`.
The base-16 dominance inequalities from the predecessor audit make numerical
order of `K` the lexicographic signature order.  Every permutation within one
cell is an automorphism of the normalized base formula: it preserves the two
degree classes, the anchor split, and every unordered edge/triangle constraint.

For each cell, the proof visits all pairs `(i,j)` in selection-sort order:
first fix `i` and visit every `j>i`, then increment `i`.  It adds
`K(i)<=K(j)` with the vertex transposition `(i j)` as a redundance witness.
There are

```text
C(6,2)+C(7,2)+C(15,2)+C(14,2)=15+21+105+91=232
```

such comparisons.  Suppose the current comparison is violated, so
`K(i)>=K(j)+1`.  Swapping `i,j` satisfies the new row.  For an earlier row
with the same pivot, `K(i)<=K(k)`, the swapped row follows from

```text
K(k)-K(i) >= 0,
K(i)-K(j) >= 1.
```

The proof supplies the explicit cutting-planes contradiction after also
assuming the negation `K(j)-K(k)>=1`; their sum is `0>=2`.  Rows belonging to
earlier pivots occur in transposed pairs and are found syntactically in the
core.  All base rows are likewise mapped to base rows.  Thus each strengthening
step preserves satisfiability.  At the end, every pair in each cell is ordered,
so the cell signatures are nondecreasing.  Every base-model orbit therefore
retains at least one labeled representative, and the converse is immediate
because the complete base formula remains in the output.

This proof pattern avoids the non-composability of adding only the 38 adjacent
comparisons one at a time: an arbitrary later adjacent swap can break an
earlier adjacent row.  The all-pairs selection order makes preservation local
and checkable.

## Reproduction

Tested with CPython 3.12.12, Apple clang 17.0.0, Rust 1.92.0, and the official
VeriPB tag `3.0.2`, commit
`c648bac06be995b82bd218e248f005140fc8ce11`.  From this directory in a clone
that also contains the sibling base-formulation directory, run:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 audit_schedule.py

PYTHONDONTWRITEBYTECODE=1 python3 \
  ../ramsey_r55_m214_complete_formulation/generate_opb.py \
  --output /tmp/r55_m214_complete.opb

PYTHONDONTWRITEBYTECODE=1 python3 generate_certificate.py \
  --input /tmp/r55_m214_complete.opb \
  --output /tmp/r55_m214_selection_ordered.opb \
  --proof /tmp/r55_m214_selection_ordering.pbp

xcrun clang++ -std=c++20 -O2 -Wall -Wextra -Wpedantic -Werror \
  -isystem /Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/usr/include/c++/v1 \
  check_certificate.cpp -o /tmp/r55_check_selection_certificate

/tmp/r55_check_selection_certificate \
  /tmp/r55_m214_complete.opb \
  /tmp/r55_m214_selection_ordered.opb \
  /tmp/r55_m214_selection_ordering.pbp
```

Obtain and build the pinned official verifier (a system Rust installation or
an isolated `RUSTUP_HOME`/`CARGO_HOME` may be used):

```bash
git clone --branch 3.0.2 --depth 1 \
  https://gitlab.com/MIAOresearch/software/VeriPB.git \
  /tmp/veripb-3.0.2
cargo build --release --manifest-path /tmp/veripb-3.0.2/Cargo.toml

/tmp/veripb-3.0.2/target/release/veripb \
  /tmp/r55_m214_complete.opb \
  /tmp/r55_m214_selection_ordering.pbp \
  /tmp/r55_m214_selection_ordered.opb
```

Compare compact stdout with `EXPECTED_OUTPUT.txt`.  The output formula has
1,974,963 source rows (128 equalities), 1,974,964 lines, 168,085,777 bytes, and
SHA-256
`d621bf525bd6e3525ef5f9ccc741dc01c66a07f39b3db4c5e63741190d75eebc`.
The proof has 3,285 lines, 6,423,184 bytes, 874 explicit cutting-planes
subgoals, and SHA-256
`38559d18edd3edff6ea809a6299562f44d10c1a6132f6a6f5246b0a530ed725b`.

The independent C++ checker imports no Python code.  It compares every copied
base row, reconstructs all 232 output rows, independently enumerates every
1,722-variable transposition, tracks temporary VeriPB constraint identifiers,
and reconstructs every proof line.  Its AddressSanitizer/UndefinedBehaviorSanitizer
build passes the same complete streams.

## References and trust boundary

The proof uses the official [VeriPB proof-format
documentation](https://gitlab.com/MIAOresearch/software/VeriPB/blob/3.0.2/proof_format_overview.md)
and the redundance framework of Bogaerts, Gocht, McCreesh, and Nordström,
[JAIR 77 (2023), 1539-1589](https://doi.org/10.1613/jair.1.14296).

Trusted components are the height-2505 base-formulation equivalence and its
inherited extremal inputs; the displayed selection-order argument; the VeriPB
3.0.2 implementation and proof-rule soundness; CPython exact integers; the C++
and Rust compilers/libraries; ordinary hardware; and SHA-256 collision
resistance.  The C++ reconstruction reduces correlated generator mistakes but
does not formalize the graph-to-base-OPB equivalence.  No solver result, model,
UNSAT claim, or generated artifact absent from the stated hashes is trusted.
